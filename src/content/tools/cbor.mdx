## What CBOR is

CBOR is JSON's data model in binary: same shapes, no text syntax, no
whitespace, and a handful of types JSON does not have. The initial byte of every
item says what it is and how long it is, which is why a decoder can read it
without knowing the schema.

It gets used where bytes matter: WebAuthn attestations, COSE signatures, IoT
payloads, and anything that has to be canonical enough to sign. A small object
that is 34 bytes of JSON is often 18 bytes of CBOR, and the page shows the
comparison for whatever you paste.

## Reading a decoded item

Three views, because they answer three different questions:

- **Diagnostic notation** — what the bytes mean, in RFC 8949's own textual form.
  This is the one to read.
- **JSON** — what most code wants, with the parts JSON cannot carry written as
  strings: big integers as digits, byte strings as hex, tags as `{"tag": …,
  "value": …}`. Those do not survive a round trip, which is the whole reason CBOR
  exists.
- **Byte by byte** — the annotated layout: one line per item with its major type
  and length, which is how you find out why two encodings of the same value
  differ.

The decoder is checked against every vector in RFC 8949 Appendix A, including the
indefinite-length ones: an item written as a stream of chunks ended by a break,
which is the part of CBOR with no JSON equivalent and the part most likely to be
handled wrongly.

## Tags, and why they matter

A tag says what a value *is*: `0` is a date string, `1` is an epoch-based time,
`2` is a big integer, `23` is a byte string that is itself CBOR, `55799` marks a
file as CBOR so that a magic-number sniff finds it. The decoder shows them rather
than resolving them, because resolving is a decision the application makes.

## Determinism

Two encoders can produce different bytes for the same value, because map key order
is not part of the data model. That is fine until something signs the bytes. The
sorting option writes keys in the deterministic order, which makes an encoding
reproducible across implementations — the property a signature needs.
