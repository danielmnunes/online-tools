## Verifying a file with SHA3-256

Drop a file above for its SHA3-256 digest. The file is streamed through the sponge
construction in your browser and never uploaded.

## Why a project would publish SHA-3

Not because SHA-2 is failing — it is not. The argument is structural diversity: SHA-2 and
SHA-3 share no design ancestry, so a break in one would leave the other standing. Some
government and financial profiles require an approved alternative to be available for exactly
that reason, and a few projects publish both digests so verifiers can choose.

In everyday use SHA-256 remains the pragmatic choice for a published checksum, because every
machine already has a tool that computes it.

## Not Keccak-256

If a digest does not match, check which function was meant. NIST added two domain-separator
bits to the padding when standardising, so SHA3-256 and the original Keccak-256 give
completely different results for the same file. Ethereum tooling means Keccak; `sha3sum` and
`openssl` mean SHA-3.
