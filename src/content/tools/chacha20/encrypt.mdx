faq:
  - q: >-
        Why not ChaCha20-Poly1305?
    a: >-
        Use that page unless you are matching a protocol that encrypts with ChaCha20 and authenticates separately — or reproducing a test vector. Unauthenticated encryption is how ciphertext gets modified in transit without anyone noticing.
  - q: >-
        8-byte nonce or 12?
    a: >-
        12. That is RFC 8439, TLS 1.3 and WireGuard. The original Bernstein ChaCha20 used 8 bytes and a 64-bit counter; this page does not offer it, because it is not what anyone searching for ChaCha20 now means.
  - q: >-
        Can I pick a random nonce?
    a: >-
        Not safely, not twice, not under the same key. A 12-byte nonce is 96 bits; random nonces collide after a few billion messages. Protocols that use ChaCha20 either count the nonce or switch to XChaCha20, which is not this page.

## ChaCha20

A stream cipher: 20 rounds of add-rotate-XOR on a 512-bit state, producing a
keystream that is XORed with the message. The IETF form in RFC 8439 takes a
32-byte key and a 12-byte nonce. There is no padding. Encryption and decryption
are the same XOR.

The counter starts at 0, which is what OpenSSL's `chacha20` does when the first
four bytes of its 16-byte IV are zero. The RFC's standalone ChaCha20 test
vector uses counter 1, because in the AEAD construction block 0 is reserved
for Poly1305. If a vector does not match, check the counter before checking
the implementation.

This page is backed by @noble/ciphers. There is no ChaCha20 in the Web Crypto
API.
