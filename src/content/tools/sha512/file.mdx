## Verifying a file with SHA-512

Drop a file above to compute its SHA-512 digest. The file is streamed through the hash in
your browser and never leaves the machine.

## The speed argument

It is counter-intuitive that the longer digest is often the faster one, but SHA-512 works on
64-bit words with 1024-bit blocks where SHA-256 works on 32-bit words with 512-bit blocks.
Per byte of input, SHA-512 does meaningfully less work on any 64-bit CPU. That is why it
appears in package management systems that hash a great deal of data.

The exception is hardware acceleration: x86 SHA-NI and the ARMv8 crypto extensions implement
SHA-256 but usually not SHA-512, and on those paths SHA-256 wins comfortably. This page runs
in JavaScript with no access to either, so here SHA-512 is the quicker of the two.

## What the checksum is for

As always, a checksum published beside the download proves the bytes are intact, not that
they are authentic. Where it matters, verify a signature over the checksum file with a key
you obtained from somewhere other than the download page.
