description: >-
  Generate passwords with crypto.getRandomValues and rejection sampling. Never Math.random. Entropy is reported in bits, not a colour.
faq:
  - q: >-
      Why not Math.random?
    a: >-
      `Math.random` is not a CSPRNG. Its output is fine for shuffling a playlist and the wrong shape for a secret. This page draws from `crypto.getRandomValues`, which is the Web Crypto CSPRNG, and it never falls back.
  - q: >-
      What is rejection sampling?
    a: >-
      Taking `byte % 64` over a 64-character alphabet is uniform; taking `byte % 62` is not, because 256 is not a multiple of 62. Bytes at or above the largest multiple of the alphabet size are discarded and drawn again, so every character is equally likely.
  - q: >-
      What do the bits mean?
    a: >-
      `length × log2(alphabet size)`. It is the entropy of a uniform draw from that alphabet, not a prediction of how long the password will last against a particular attacker. A 20-character password from 72 symbols is about 123 bits. A colour bar that says "strong" is not more information than that.
  - q: >-
      Is this a password manager?
    a: >-
      No. It mints a string and leaves it on the screen. It does not store, sync, or remember. Closing the tab forgets it. If you need storage, that is a different program.

## A CSPRNG, an alphabet, a length

The generator draws uniformly from the character sets you tick. Ambiguous characters (`0`, `O`, `I`, `l`, `1`) can be dropped. "At least one of each set" takes one character from every selected set, fills the rest from the pool, and shuffles with Fisher–Yates — also from `crypto.getRandomValues` — so the guaranteed characters are not sitting at the front.

Nothing is sent anywhere. The number under the result is bits of entropy against a brute-force guess of this alphabet, which is the only number this page can honestly give.
