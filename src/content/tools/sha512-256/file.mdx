## Verifying a file with SHA-512/256

Drop a file above to compute its SHA-512/256 digest: 64 hexadecimal characters, the same
length as SHA-256 but a different function.

Hashing happens locally, streamed through the file so that multi-gigabyte inputs work
without loading anything fully into memory.

## The variant that deserved more adoption

SHA-512/256 gives the same 128-bit collision resistance as SHA-256, runs faster in software
on 64-bit processors, and cannot be length-extended. On the technical merits it is the better
32-byte hash from the SHA-2 family.

What it never got was ubiquity. `sha256sum` is on every machine; there is no `sha512-256sum`.
SHA-256 has dedicated CPU instructions that no software SHA-512 variant can match. For a
published checksum, being the thing everyone can verify is itself a feature — which is why
SHA-256 remains the right default despite this.

## Telling them apart

Both produce 64 hex characters, so a mismatch gives no hint about which function was meant.
If a checksum fails, check the algorithm before checking the file.
