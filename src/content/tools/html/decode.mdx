## What decoding does

It takes character references — `&amp;`, `&#38;`, `&#x26;` — and gives you back
the characters they stand for. That sounds trivial and is not quite, because the
rules for matching a reference are not "find the semicolon":

- A reference ends at the first `;` if there is one.
- If there is none, the parser takes the longest prefix that names a character.
  So `&notit;` decodes to `¬it;`, and `&amp` without its semicolon still decodes
  to `&`.
- Numeric references in the range 0x80–0x9F are remapped to the characters
  Windows-1252 puts there, because that is what billions of existing documents
  mean. `&#151;` is an em dash, not a control character.
- Out-of-range and undefined numeric references become U+FFFD rather than being
  rejected, per the standard.

All of that is the browser's behaviour, because it is the browser doing the work.

## How, and why that is the right answer

The input is parsed as HTML by the browser, with every literal `<` escaped first
so that no element can be created, and the resulting text is read back. The node
is never inserted into the page.

That gives correct behaviour on all ~2 231 named references, on the C1 remapping,
and on malformed input, for zero bytes of downloaded table and with no
transcription risk. It also means the answer is the same one the browser will
give the string in a page, which is what matters if you are trying to work out
what a document actually says.

The escaping step is what makes it safe: with no `<` in the input, parsing can
produce text nodes and nothing else, so nothing can be fetched and no script can
run — even if what you paste is a fully-formed injection attempt.

## When the result looks wrong

If a reference decodes to U+FFFD, the number was outside the range that maps to a
character: above U+10FFFF, or in the surrogate range. If a named reference comes
back as itself, it is not one of the named references — a trailing semicolon and
the exact spelling both matter, and `&nbsp` without the semicolon works while
`&nbps;` does not.
