## Hashing a file with Keccak-256

Drop a file above for its Keccak-256 digest — the original competition version, not the
standardised SHA3-256. The file is read and hashed in your browser.

## Why this page is separate from SHA3-256

NIST appended two domain-separator bits to the padding when finalising FIPS 202 in 2015.
Ethereum had shipped a few weeks earlier using the competition version and could not change
without a consensus break. The two functions are otherwise identical and produce completely
different digests.

The failure mode is silent: a library's `sha3_256` returns a perfectly valid 64-character
digest that simply is not what Solidity computed. If a hash does not match what a contract
expects, checking which function you used is the first thing to try.

## Ethereum artefacts worth hashing

Deployed bytecode, for `EXTCODEHASH` and `CREATE2` addresses. Serialised RLP structures, for
trie nodes. Any file whose digest a contract will compare against a stored value.
