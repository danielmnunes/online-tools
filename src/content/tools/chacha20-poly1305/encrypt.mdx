faq:
  - q: >-
        What is associated data for?
    a: >-
        Bytes that must be authentic but not secret: a header, a packet number, a content type. They are not encrypted. They are mixed into the Poly1305 tag, so decrypting with the wrong associated data fails the same way a wrong key fails.
  - q: >-
        Can I generate a random nonce?
    a: >-
        The same warning as ChaCha20: a 12-byte nonce under a long-lived key is not large enough for random generation. Count it, or do not reuse the key. XChaCha20-Poly1305 takes a 24-byte nonce and is not this page.
  - q: >-
        Where is the tag?
    a: >-
        Appended. Decrypting expects the last 16 bytes to be the tag. If a library gave you them separately, concatenate before pasting into the decrypt page.

## ChaCha20-Poly1305

ChaCha20 for encryption, Poly1305 for a 16-byte tag over the ciphertext and
the associated data. RFC 8439 is the IETF construction used in TLS 1.3, SSH
and WireGuard. The nonce is 12 bytes; the key is 32.

A wrong key, a wrong nonce, a wrong associated-data string or a flipped bit
all fail authentication. Nothing is returned. That is the contract, and it is
why this page exists next to the unauthenticated ChaCha20 one rather than
instead of a checkbox.

Backed by @noble/ciphers. The Web Crypto API does not include this AEAD.
